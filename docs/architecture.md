# Architecture

```text
ODB++ ZIP/TGZ/TAR/folder
      |
      v
OdbParser
  - locate matrix/matrix
  - identify step and signal layers
  - parse EDA net map
  - parse layer feature attribute tables (@ names and & text strings)
  - parse layer features and decode raw feature attributes
      |
      v
FeatureRecord geometry
  - track buffer geometry
  - pad flash geometry
  - polygon surface geometry
  - raw attributes, e.g. 0=5,3=0.3
  - decoded attributes, e.g. .string=C21, @3=0.3
      |
      v
ClearanceAnalyzer
  - group features by layer + net
  - union copper per net
  - measure pairwise same-layer spacing
  - compute per-net minimum
      |
      v
ReportWriter
  - full CSV
  - critical CSV
  - per-net CSV
  - decoded feature attributes CSV
  - XLSX workbook with Feature attributes sheet
  - Markdown report
  - ZIP report package
      |
      v
GUI / CLI / Python API
```

## Data flow details

1. `OdbParser.parse()` extracts ZIP/TGZ/TAR input if necessary.
2. It reads `matrix/matrix` and selects layers where `TYPE=SIGNAL` or `TYPE=POWER_GROUND`.
3. It reads `steps/<step>/eda/data`; `FID C <layer_index> <feature_index>` assigns copper features to the current net.
4. It reads each signal layer's `features` file, decodes the `@` attribute-name table and `&` text-string table, then creates one `FeatureRecord` per top-level feature with both raw and decoded attributes.
5. `ClearanceAnalyzer` groups features by `(layer, net)` and unions them into one Shapely geometry per net.
6. For each layer, every net pair is measured using Shapely distance and nearest-point calculation.
7. Reports are generated from the measurement records and decoded feature-attribute records.

## Accuracy model

The program measures design geometry as exported in ODB++. It is not a substitute for CAM DRC or certification lab review. Manufacturing expansion/etch tolerances, solder mask registration, contamination, coating, and safety standard interpretation must be handled separately.


### Rounded rectangular pad handling

Rounded rectangular KiCad/ODB++ symbols with an `xr` suffix, for example `rect1600.0x1600.0xr400.0`, are represented as rounded rectangles. Earlier versions used the bounding rectangle as a conservative approximation; this could create artificial copper at square corners and report false clearances around 0.04 mm near pads.

Nearest-point coordinates in the measurement CSV are generated by Shapely from the reconstructed geometry and may lie on pad/zone boundaries. They should not be interpreted as original track endpoints.

## v0.1.4 geometry-compositing notes

The analyzer does not read ready-made clearance numbers from ODB++. It reconstructs same-layer copper geometry and measures distances with Shapely.

For each physical copper layer the analyzer now performs ordered polarity compositing:

1. Positive features are accumulated by net.
2. When a negative/cutout feature is encountered, pending positive features are flushed to the current layer geometry.
3. The negative/cutout geometry is subtracted from all copper accumulated so far.
4. Later positive features are still allowed to add copper again.

This is needed for copper pours and plane layers where anti-pads and isolation openings may be represented as negative features. Skipping those features makes the pour appear to overlap pads from other nets and creates false `0 mm` clearances.

The parser also strips inline ODB++ attributes from EDA net-name records. For example, `GND ; 0=0,3=0.3,` is treated as net `GND`; the semicolon suffix is metadata.


## Geometry debug layer

The analyzer now keeps a diagnostic link between reported critical pairs and original ODB++ features. After the normal per-net geometry has been composited and measured, the first `debug_limit` critical pairs are inspected again. The debug layer records relation predicates, overlap area/length, composed geometry bounds, source positive features near the reported closest points, and negative/cutout features nearby.

This is useful when a reported clearance is `0 mm`. A true short, an unsupported negative/cutout primitive, an ODB++ export without filled-zone clearances, or a symbol parsing bug can all appear as zero distance in the final composed geometry. The debug report makes those cases visible instead of only showing Point A = Point B.


## Pad orientation handling

ODB++ pad features can encode orientation using compact integer `orient_def` values. The parser decodes the rotation component of codes `0..7` before creating Shapely geometry. Mirroring is ignored for standard round/rectangle/oval pad outlines because it does not change the physical clearance body, but the rotation component is essential for non-square pads. Literal degree tokens such as `90.0` or `270.0` are passed through unchanged.


## GUI geometry viewer

The GUI includes `odb_clearance_analyzer.geometry_viewer.GeometryViewer`, a standalone Tkinter `Toplevel` window that renders `AnalysisResult.net_geometry_by_layer`. This is deliberately the same composed Shapely geometry used by the clearance calculation rather than a separate CAD-rendering pipeline.

The viewer provides layer selection, Net A/Net B highlighting, optional other-net underlay, measurement-point markers, mouse-wheel zoom, drag panning, and fit-to-selection. It is intended for diagnosing false `0 mm` rows and verifying whether a suspicious result comes from real reconstructed geometry overlap or from parser/export limitations.


## Surface contour parsing

Version 0.1.8 parses ODB++ surface commands `OB`, `OS`, `OC`, `OE`, and `SE`. `OC` circular arcs are tessellated into short segments before Shapely polygon construction. Without this step, rounded pour edges or anti-pad boundaries can become broken straight-line contours and may produce false small clearances to pads.

## v0.1.9 geometry viewer click selection

The geometry viewer can now select nets directly from the canvas:

1. First simple left-click on reconstructed copper selects **Net A**.
2. Second simple left-click on a different reconstructed copper net selects **Net B**.
3. The selected pair is redrawn and highlighted using the same composed Shapely geometries used by the clearance engine.

Hit testing converts a small screen-space tolerance into millimetres and searches all nets on the selected layer. When more than one net is under the click point, the viewer prefers the smallest geometry area so that pads/tracks are easier to select than large copper pours.


## v0.2.0 persistent geometry-viewer selection across layer changes

Geometry-viewer net selections are now treated as viewer-level state, not layer-local state. Changing the layer refreshes the combobox candidate list but does not clear `Net A` or `Net B`. The draw path resolves those selected names against the active layer each time, so the same selected pair is highlighted automatically wherever it exists. The status bar reports selected nets that are not present on the active layer.


## GUI theme layer

Version 0.2.2 adds `odb_clearance_analyzer/theme.py`, a dependency-light Material/Android-inspired ttk theme used by the main GUI and geometry viewer. It centralizes the color palette, app-bar, card, button, notebook, status label, and table styling so future GUI features stay visually consistent.


## Plated via projection

Version 0.2.2 adds a via-projection stage after normal copper-layer compositing. The parser reads ODB++ `TYPE=DRILL` layers whose names indicate plated drills and whose matrix records provide `START_NAME`/`END_NAME`. Drill features assigned to nets through `FID H` records are converted to via pad geometry and merged into each signal layer in the drill span.

The projected via geometry is stored separately in `AnalysisResult.via_geometry_by_layer` for viewer overlays, and it is also merged into `AnalysisResult.net_geometry_by_layer` before measuring clearances. This keeps the geometry viewer and analyzer consistent: what the viewer displays is what the analyzer measures.

Pad diameter inference order:

1. ODB++ feature attribute text such as `VIA_ROUNDD700000` is interpreted as a 0.700000 mm via pad.
2. If no pad-size metadata is available, the drill feature symbol diameter is used as a visibility fallback.

The fallback is intentionally conservative for visualization only; for formal clearance checking, prefer ODB++ exports that include explicit via pad geometry or clear via pad attributes.


## Cooperative cancellation

The GUI runs analysis in a worker thread and passes `cancel_event.is_set` into `ClearanceAnalyzer(cancel_check=...)`. The analyzer checks this callback at safe points inside long loops, including feature compositing, net-pair measurement, Effective Net-to-Net distance calculation, blocker-net inspection, and debug diagnostics. When cancellation is requested, the analyzer raises `AnalysisCancelled`, which the GUI treats as a clean stopped state rather than a failure.

This design avoids unsafe thread termination. It also means Stop is cooperative: very large Shapely operations may finish their current operation before the cancellation exception is raised.

## Version 0.2.6 GUI additions

The root `run_gui.py` launcher starts the Tkinter GUI directly and is used by `build_windows_exe.bat` as the PyInstaller entry point. The package also includes `odb_clearance_analyzer.run_gui` so the GUI can be launched with `python -m odb_clearance_analyzer.run_gui`.

The Geometry Viewer now has independent Net A and Net B filter fields. Filters are applied only to the combobox drop-down choices; they do not clear the selected net value. This keeps cross-layer inspection behavior predictable when the selected net is not present on the active layer.

## Geometry viewer pad overlay

From v0.2.8, the Geometry Viewer can draw component-pad features separately from the merged per-net copper geometry.  The analyzer still calculates clearance from the unioned copper bodies, but the viewer overlays original positive `P` features from the signal-layer ODB++ feature files.  This helps debug IC/component pads that are otherwise visually hidden inside a selected net polygon or a large copper pour.


## v0.2.9 GUI table rendering

The main GUI table widgets are now created through a shared scrollable-table helper.  Each table is placed in a dedicated grid-managed frame containing the `Treeview`, a right-side vertical scrollbar, and a bottom horizontal scrollbar.  This avoids mixed `pack`/`grid` problems and keeps scrollbars aligned with the table body.

The GUI also has an optional clearance-gradient visualization.  Row tags are assigned from the active threshold so low-clearance rows are shown in the red range, mid-clearance rows in amber, and rows at or above the threshold in green.  Theme changes and the gradient checkbox both reapply row tags without rerunning analysis.


## Electrical Settings / Voltage Estimate

The analysis configuration stores CTI, pollution degree, and altitude. The voltage estimator maps measured spacing to a conservative `Effective max voltage V` screening value using CTI/material group, pollution scaling, and altitude correction. The result is intended for engineering review only and must not be treated as formal IEC/UL certification.

## Layer-role and IPC-2221A estimate

The GUI can pre-read ODB++ metadata and populate an editable per-layer role table. Layer roles are passed into `AnalysisConfig.layer_roles`. The analyzer uses these roles to add `ipc2221a_max_voltage_v`, an IPC-2221A/B-style conductor-spacing estimate that distinguishes internal and external layers. External layers at altitude above 3050 m use the high-altitude external table class.

## IEC 60664-1 per-layer pollution model

`AnalysisConfig` carries per-layer IEC pollution degrees, external conformal coating state, and metallic particle size. The analyzer uses IPC layer roles as an input to default IEC pollution degrees: internal layers default to PD1; external layers use the base pollution degree or PD2 when external conformal coating is selected. Metallic particle size is subtracted from external-layer measured spacing before estimating the IEC-style Effective max voltage V.
